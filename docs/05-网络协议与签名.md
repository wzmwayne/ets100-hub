# 05 · 网络协议与签名

## 1. 客户端网络栈

App 有**两套**网络栈：

| 栈 | 类 | 说明 |
|---|---|---|
| Ktor | `com.ets100.network.EtsHttp` + `NxtHttpClient` | 可读 Java/Kotlin |
| Retrofit(OkHttp) | `com.ets100.secondary.model.api.ServiceGenerator` | 由 native (`JniLib`) 构建 |

两者的拦截器（`com.ets100.network.ets.interceptor.EtsGzHttpInterceptor` /
`EtsHfHttpInterceptor` / `...model.api.interceptor.EtsHttpInterceptor`）
负责**统一包装**：加公共参数、Base64、签名、Referer。

实测（运行时反射读出）：

```
Retrofit.baseUrl() = https://api.ets100.com/
OkHttpClient.interceptors = [ com.ets100.secondary.model.api.interceptor.EtsHttpInterceptor ]
Options(etsApp=0, etsApi=ets/api/, gzConf=Conf(hostIp=https://api.ets100.com,
        baseUrl=https://api.ets100.com), hfConf=Conf(.../ets/api/), isOnNewGray=false)
```

## 2. 请求格式

### 2.1 URL

```
POST https://api.ets100.com/<r>
```

**路径就是接口名本身**（`r`），不是根路径：

```
POST https://api.ets100.com/g/pk/count          ✅ 200
POST https://api.ets100.com/                    ❌ {"code":10003}
POST https://api.ets100.com/ets/api/g/pk/count  ❌ 400 (istio-envoy, flow_key: old)
```

### 2.2 内层（明文 JSON）

```json
[{
  "r": "g/pk/count",
  "params": {
    "system": "2",
    "global_client_version": "7.0.67.2495(2495)",
    "sn": "17904002547006811",
    "token": "<JWT>",
    "ets_app": "0",
    "sign_response": 2,
    "...": "各接口自己的参数"
  }
}]
```

> 内层虽然是数组，但**服务端只处理第一条**，无法用它批量合并请求。

### 2.3 外层

```json
{
  "body": "<Base64(内层JSON字符串, UTF-8)>",
  "head": {
    "sign": "<签名>",
    "pid": "androidV3",
    "time": "1790400266771",
    "time_second": 1790400266771,
    "version": "1.0"
  }
}
```

### 2.4 请求头

```
Content-Type: application/json; charset=UTF-8
Referer: https://api.ets100.com
User-Agent: okhttp/4.9.3
Accept-Encoding: gzip            ← 响应可能是 gzip
```

（`ets-tag: gray` 仅在 `isOnNewGray=true` 时加，本账号为 false）

## 3. 签名算法（核心）

### 3.1 反汇编过程

```bash
aarch64-linux-gnu-objdump -d --start-address=0x62a4c --stop-address=0x62d4c \
    apktool_out/lib/arm64-v8a/libmd5.so
```

函数 `Java_com_ets100_secondary_utils_JniUtils_getSign @ 0x62a4c`：

```asm
62a74: adrp x1, 46000 ; add x1, x1, #0xb7e   → 常量1 @0x46b7e = "androidV3"
62a7c: ...           ; std::string s1 = "androidV3"
62a84: adrp x1, 46000 ; add x1, x1, #0x59f   → 常量2 @0x4659f = "717e3cdc7314959fa2ef469d38f05673"
62a8c: ...           ; std::string s2 = "<KEY>"
62aa4: GetStringUTFChars(input)              ; s3 = 传入的字符串 (time + body)
62ac4/62ad8: 两个 string 拼接 helper
62ae8: MD5(str)                              ; MD5::MD5(const std::string&)
62b08: MD5::toStr()
```

拼接顺序经 4 组样本验证为 **pid + input + key**：

```
sign = MD5("androidV3" + str(time) + body + "717e3cdc7314959fa2ef469d38f05673")
```

### 3.2 血泪教训：密钥抄错一位

第一次分析时把 `0x4659f` 读成了 `317e3cdc...`（首位 `3` 而非 `7`），
导致所有自建请求都返回：

```json
[{"code":10003,"msg":""}]
```

试遍了 16 种组合（大小写/顺序/双哈希/UTF-16…）都不对。
**最终是用 app 自身做签名 oracle 比对才定位到密钥抄错**。

正确密钥：`717e3cdc7314959fa2ef469d38f05673`

Python 实现：

```python
import hashlib
SECRET = "717e3cdc7314959fa2ef469d38f05673"
def sign(data):                      # data = str(time) + body
    return hashlib.md5(("androidV3" + data + SECRET).encode()).hexdigest()
```

Java 实现见 `shim_java/plugin_sample/src/.../SuperAutoPkPlugin.java` 的 `md5()`。

### 3.3 响应校验

响应头 `Sign` 由 `JniUtils.getResponseSign(base64(responseBody, NO_WRAP), sn)` 校验。
客户端侧未通过会丢弃响应体（返回空）。自建客户端可忽略。

## 4. 常用错误码

| code | 含义 | 常见原因 |
|---|---|---|
| 0 | 成功 | — |
| 10000 | 请求格式非法 | GET 请求 / 外层 JSON 不合法 |
| **10003** | 签名校验失败 | 密钥/拼接口令错、body 与签名不一致 |
| 500 | Unable to resolve the request | `r` 路径不存在（如发到了根路径） |
| 9001 | API_SERVICE_INNER_INVALID | 业务参数不合法（例如 73 个词超过上限） |
| 9002 | DATA_SERIALIZATION_INVALID | 参数类型错（如 `word_ids` 传了数组而非字符串） |

## 5. 手写请求示例（curl 形态）

```bash
python3 - <<'PY'
import base64, hashlib, json, time, random, urllib.request
SECRET="717e3cdc7314959fa2ef469d38f05673"; PID="androidV3"
TOKEN="<从 /account 取>"; VER="7.0.67.2495(2495)"
r="g/pk/count"; t=int(time.time()*1000); ts=str(t)
params={"system":"2","global_client_version":VER,"sn":ts+"1234",
        "token":TOKEN,"ets_app":"0","sign_response":2}
inner=[{"r":r,"params":params}]
body=base64.b64encode(json.dumps(inner,separators=(',',':'),ensure_ascii=False).encode()).decode()
sign=hashlib.md5((PID+ts+body+SECRET).encode()).hexdigest()
outer={"body":body,"head":{"sign":sign,"pid":PID,"time":ts,"time_second":t,"version":"1.0"}}
req=urllib.request.Request("https://api.ets100.com/"+r,
        data=json.dumps(outer,separators=(',',':')).encode(),
        headers={"Content-Type":"application/json; charset=UTF-8",
                 "Referer":"https://api.ets100.com","User-Agent":"okhttp/4.9.3",
                 "Accept-Encoding":"gzip"})
import gzip
raw=urllib.request.urlopen(req,timeout=20).read()
try: raw=gzip.decompress(raw)
except Exception: pass
print(raw.decode())
PY
```

## 6. 账号配置来源

运行时从 App 反射读取（插件内）：

| 值 | 取法 |
|---|---|
| token | `EtsHttp.a.h().a()` |
| ets_app | `EtsHttp.a.f().a().i()` → "0" |
| baseUrl | `EtsHttp.a.f().a().j().e()` → "https://api.ets100.com" |
| client_version | `od.a.a.d()` → "7.0.67.2495(2495)" |

HTTP 方式：`GET http://127.0.0.1:8765/account`（`PkApiPlugin` 提供）

## 7. 性能优化记录（自建客户端）

| 优化 | 效果 |
|---|---|
| 签名本地化（不再 HTTP 调 App） | 去掉串行瓶颈 |
| OkHttp/HttpURLConnection **keep-alive 复用连接** | 单线程 13.7 → 101.7 局/分 |
| 词表/结构按单元缓存 | 每局请求 4 → 2 |
| 动态并发（峰值追踪） | 峰值 17~19 局/秒 |

**上限在服务端**：裸请求约 80 请求/秒，每账号约 40 请求/秒（=2 请求/局 ⇒ ≈20 局/秒），
并发超过 ~50 线程后吞吐反而下降。
